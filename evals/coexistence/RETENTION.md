# CMA guidance retention audit

The first rewrite omitted useful project-detection instructions. Token and coexistence checks did not establish that every useful instruction survived. This audit compares every section of the [original CMA entrypoint](https://github.com/datocms/agent-skills/blob/94e4bd8128e52963829f65bce8f202fcd68ac8d6/skills/datocms-cma/SKILL.md#L1-L315) with its current destination. It is a semantic review, not a claim of identical wording or universal model behavior.

The correction restores existing client/package/configuration detection, existing type-module reuse, explicit CMA credential scope, package-consistent helper/error imports, the secondary-branch migration preference, the locale-backfill reference, explicit CLI argument guards, named error handling, and long-script progress reporting. Shared decisions remain in the entrypoint; runtime-specific details stay in the relevant reference.

Paths below are relative to `skills/`. “Retained” includes equivalent instructions and existing reference examples; “restored” identifies details added back by the correction. All old line ranges refer to the pinned source above.

`records.md` and `editing-records.md` keep their original paths and substantive workflow sections. Their edits separate CLI lookup hints from shared prose, make imports/runtime type recovery conditional, and turn invalid example prose into a code comment. The exact server filter and substantive-section comparisons are exercised by the existing compatibility tests.

This audit closes the identified instruction omissions. It does not turn the earlier 126-session routing evaluation into a test of every local application workflow. The additional local-authoring fixture specifically checks inspection and reuse of an existing client and generated type module, compiles the returned helper, and executes it against a synthetic client. Prior behavioral evidence remains tied to its recorded revision.
