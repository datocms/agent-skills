# Current DatoCMS MCP

Load only after selecting MCP. It is optional; do not install or configure it as a prerequisite for CLI work.

1. Use the DatoCMS tools actually exposed in this conversation. Their current descriptions define authentication, project/environment selection, method discovery, script syntax, available helpers/types, and execution requirements. Do not guess tool prefixes or require a tool that this client does not expose.
2. Reuse the established project and environment. Resolve missing targets through the available tools; ask only when the intended target remains ambiguous. Respect the connection's granted permissions and the user's requested scope. If access is already read-only, stop before submitting a mutation; do not test the restriction with a write.
3. Request only the relevant schema and methods. Follow the tool's documentation/verification requirements before constructing a script. Use its supplied client, types, and helpers; do not initialize local CLI configuration, construct another authenticated client, or request a token for this route.
4. Use a write-capable execution tool for a script containing a mutation, even if it also reads first. Read-only execution is for inspection and verification; it is not a dry-run validator for mutations. Keep preconditions and the single update together. Before updating, log the actual original fields, locales, references, and publication state needed for preservation checks. Return those values, not just presence flags or counts: script variables do not persist between executions.
5. Verify in a separate read-only script against that captured evidence. Never invent original values or substitute example constants. Compare meaningful saved values, not `serialize()` output or whole-tree request/response equality. If a comparison fails, inspect read-only; do not repeat the update or discard the comparison as proof of preservation. Report only what was verified.
6. Apply the task's existing CMA reference and preserve unrelated content. Keep nested Structured Text response snapshots separate from request values. Bind checked locales to non-null constants before callbacks; reapply guards after indexing or finding. Use optional access for marks and link metadata; unmarked spans accept omitted or empty marks with `(span.marks?.length ?? 0) === 0`. Reuse guidance already returned by MCP; load references only for missing task knowledge. CLI documentation hints apply only to CLI execution.
7. A timeout or missing response does not prove a write failed: inspect its outcome before retrying, and never repeat an uncertain write through a different route. Authentication and permission errors are not reasons to bypass the selected connection.

For a confirmed legacy MCP, direct the user to the [current DatoCMS MCP setup](https://www.datocms.com/docs/mcp-server) and stop using the legacy integration. Do not execute, repair, reinstall, or change its configuration. A connection error alone does not identify a legacy MCP.
