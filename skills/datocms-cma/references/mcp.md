# Current DatoCMS MCP

Load only after selecting MCP. It is optional; do not install or configure it as a prerequisite for CLI work.

1. Use the DatoCMS tools actually exposed in this conversation. Their current descriptions define authentication, project/environment selection, method discovery, script syntax, available helpers/types, and execution requirements. Do not guess tool prefixes or require a tool this client does not expose.
2. Reuse the established project and environment. Resolve missing targets through the available tools; ask only when the intended target remains ambiguous. Respect the user's requested scope and the access level the account granted this connection (view-only, content-only or unrestricted, reported with the account): check it before planning a write. If access is read-only, stop before submitting a mutation; do not test the restriction with a write.
3. Request only the relevant schema and methods. Record guides arrive in parts: core sections first, then the titles of the others (blocks, Structured Text, locales, verification). Request the listed section the task needs from the same tool; don't work from a partial guide. Follow the tool's documentation/verification requirements before constructing a script. Check its implicit globals and importable packages: when only `client` and `Schema` are supplied, import the helper values and types you use. Do not assume CLI stdin globals exist in MCP. Do not initialize local CLI configuration, construct another authenticated client, or request a token for this route.
4. Use write-capable execution for mutations; read-only execution cannot validate a write. Keep the original read, preconditions, one update, and a fresh read-back in the same script. Preserve an independent original snapshot before transforming content, then compare saved values with those in-memory originals. Script output is cut to about 2,000 characters: print compact evidence (IDs, counts, changed values), never whole records, and print the original evidence before writing so an interrupted execution remains diagnosable.
5. Read a published version only when `meta.published_at` is non-null; never-published records return `NOT_FOUND`. After a write may have run, never rerun the mutation to repair verification. Continue read-only, retaining actual originals; do not invent them or discard a failed comparison. Report only verified facts. Script variables do not persist between executions.
6. For Structured Text, follow `references/editing-records.md`'s typed transformation pattern: pass the nested response into `mapNodes`, and annotate its result as the request type. Do not serialize rewritten request blocks. Bind checked locales before callbacks. Use `collectNodes(checkedLocale, guard).map(...)` for inferred snapshots of nested spans/blocks; avoid root-child type annotations and untyped array accumulators. Use `isDeepStrictEqual` from `node:util` for object values; `===` compares identity. Treat omitted marks like `[]`; use optional link metadata.
