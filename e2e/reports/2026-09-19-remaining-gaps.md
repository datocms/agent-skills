The first Nuxt run exposed an evaluator assumption: it required HTTP 200 at `/` even though the task only required article routes. Listener readiness now accepts an HTTP response, while article checks still verify content. Two corrected rechecks then confirmed a real defect: the host received the next record ID under the previous route. Nuxt's delayed `useRoute()` update arrived after the new DOM was stamped. The canonical Nuxt controller example now updates its path in `router.afterEach`, before rendering, and owns its routing callback so parent listeners cannot merge into a non-callable array. A fresh setup later omitted the controller and invoked the browser subscription during SSR; a local transport probe reproduced `window is not defined` before any request. The Nuxt introduction now links directly to the required controller and client-only subscription examples. The second fresh setup lost request context after an awaited import and returned Nuxt E1001 on public reads. A later fresh implementation repeated the same request-context failure. Both remain failed attempts; the Nuxt reference now states that context helpers must run before awaiting, and frontend verification requires served-page checks as well as a build. Its repair also exposed a shared-reference bug: H3 cookie helpers were not imported outside Nitro's server directory. The reference now imports them explicitly. A separate failed implementation assumed a raw preview record already contained SDK-specific type metadata; the shared preview reference now distinguishes those payloads.

SvelteKit's initial public query selected `_editingUrl` without `baseEditingUrl`. The shared Content Link guidance and copied Next.js, Nuxt, SvelteKit and Astro query examples now retain the public editing origin whenever that field is selected, while draft tokens and stega stay restricted to preview. Its repaired app exposed a second defect: `querySubscription` captures initial options and does not follow reused page props. The page example now uses a keyed child and reads the returned store correctly.

Astro's initial live-update timeout was an evaluator startup race. Its supported QueryListener uses the first subscription event as a baseline. Waiting for that event before editing CMS content let the unchanged application pass. No Astro skill change was made for this failure. Astro may automatically reload; React, Vue and Svelte cases still require updates without a document reload.

Checking rendered content after navigation did not detect Nuxt's abandoned subscription. The stronger browser assertion found both EventSources open after switching records. A guided repair closes the old connection, but its credential output prevents an overall pass. A separate diagnostic reproduced two lifecycle failures with the installed Vue SDK: subscriptions created after an awaited fetch lose their owner, and disposal while the connection is opening can miss the asynchronously registered cleanup. The Nuxt reference now registers scope disposal before awaiting and closes a listener that finishes connecting after disposal. The setup recipe and shared library routing now point to the same listener pattern. The literal example typechecks, and deterministic probes verify normal disposal, disposal during fetch, disposal during connection startup and published reads. These use real Vue scopes with controlled transport; they are diagnostic evidence, not additional live model evaluations.

The public-site fixture initially supplied nonlocalized global SEO to a bilingual project; it failed before a model session. The next attempt exposed an evaluator assumption: the official RSCImage places responsive candidates on `picture` sources. The unchanged application passes once those candidates are accepted. Video checks likewise needed evaluator corrections for Mux's initial overlay versus active control-bar buttons and its undefined no-error value. All failed checks remain in the ledger; none justified changing the image or video guidance. The successful video recheck verifies actual playback through completion and cleanup.

All live attempts in this checkpoint, including the timed-out run, have verified cleanup. Temporary delivery tokens are revoked, test plugins and sandboxes removed, and the primary baseline compared after cleanup. A completed implementation that prints credentials fails its privacy grade even if separate functional checks pass; failed or ungraded earlier attempts retain their original classification.
